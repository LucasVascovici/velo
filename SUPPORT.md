# Getting help

Velody is maintained by one person, so responses are best effort.

- **A question or an idea:** open an issue (the "Feature request" form, or a
  plain issue for a question). Search the existing issues, the
  [README](README.md) and [`docs/`](docs/) first. Expect a first reply within
  about a week; it can be slower around holidays.
- **A bug:** open an issue with the "Bug report" form. Include `velody --version`,
  your platform, and the output of `velody fsck`. A reproduction that starts from
  an empty directory is answered fastest.
- **A security vulnerability:** do not open a public issue. Follow
  [SECURITY.md](SECURITY.md), which uses GitHub private vulnerability reporting
  and states what response to expect.
- **Contributing a change:** see [CONTRIBUTING.md](CONTRIBUTING.md).
- **Conduct concerns:** see [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

GitHub Discussions is not enabled, so questions go to issues. There is no paid
support and no response-time guarantee.
